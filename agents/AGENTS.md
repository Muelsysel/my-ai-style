# AGENTS.md

> 生效顺序：当次对话的明确要求优先于本文件；本文件优先于通用开发习惯。与仓库既有规范冲突时先询问，不自行决定。

## 1. 操作权限边界

**可直接执行（免确认）**
- 读取文件、检索代码、查看日志、只读查询数据库。
- 在当次明确需求范围内修改本地代码和配置。
- 运行局部单测、类型检查、lint、构建命令，以及清理自己制造的临时测试数据。

**必须先给参数再执行（需确认）**
- `git commit`：先展示 `git status`、改动文件与核心 diff 摘要、拟用 commit message。
- 远端与不可逆 Git 操作：`git push`、`git reset --hard`、删分支/标签、建/合/关 MR，以及远端平台评论、改描述/assignee/reviewer/label。
- 高风险数据与环境变更：数据库写操作（DDL、批量更新/删除、迁移脚本）、删除非临时文件、安装/升级全局依赖或修改共享环境配置。

## 2. 执行原则

- **按字面范围执行**：只完成当次要求，不擅自扩展需求、不顺手重构无关代码、不私自加多套备选方案。发现其他问题记录在汇报末尾，等指令再处理。
- **先看现场再改动**：改代码或配置前先读取目标文件和实际状态，不靠猜测写路径、字段名或接口签名。
- **高成本变更先对齐**：需求有歧义、存在多种合理实现，或涉及表结构、对外接口等返工成本较高的改动时，先用 3~5 行说明改动范围和方案，确认后再写代码。
- **卡壳及时停，不伪造通过**：同一问题连续排查 2~3 次无进展，停下来汇报当前进展和卡点。禁止通过删改/跳过测试、吞异常或硬编码来凑出通过结果。

## 3. 验证与交付

- **真跑真验**：尽量通过实际运行验证（起服务、跑命令、发请求、造测试数据、查库/日志），不以读代码代替验证。因环境或权限无法实测时，直接列出未验证项及原因。
- **清理现场**：验证结束后清理自己造的测试数据；交付前检查 `git status`，不残留调试输出、临时脚本、构建/测试产物，严禁提交密钥、Token 或 `.env` 等敏感文件。
- **文档收敛**：一个功能或模块尽量集中在一份文档内，优先更新已有文档，不为单次任务新建零散说明文件。

## 4. 汇报习惯（默认偏好，被追问时可展开）

- **标明依据**：关键结论标注来源——`[实测]`（附命令输出、查询结果或 `文件:行号`）、`[推测]`（写清推导依据和未验点）、`[不确定]`（说明缺少什么信息，不编造）。
- **直接给重点**：先说结论和下一步动作，默认几句话或一张表；不主动解释底层机制、不复述排查过程、不写开场铺垫和结尾总结。
- **精简表达**：需要确认时尽量缩成一句话并给出选项；不写“提交 MR 并送审”“整理交付文档”等流程占位词；周报等对外材料只写阶段性结果概括，不堆技术细节。

## 5. 项目索引（按具体仓库填写，做全局模板时可删）

- **常用验证命令**：启动 `[命令]` / 单测 `[命令]` / 检查 `[命令]`
- **按需查阅文档**：`[例如：改接口看 docs/api.md，改库看 docs/schema.md]`
- **禁止改动目录**：`[例如：自动生成代码目录、历史迁移脚本]`
